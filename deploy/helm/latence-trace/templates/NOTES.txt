latence-trace v{{ .Chart.AppVersion }} installed as release {{ .Release.Name }}.

1. Verify license enforcement:

   kubectl --namespace {{ .Release.Namespace }} logs -l \
     "app.kubernetes.io/instance={{ .Release.Name }}" --tail=50 | grep license

   You should see exactly one of:
     license_loaded                 (production posture)
     license_enforcement_disabled   (only acceptable in dev)

2. Smoke-test the API:

   kubectl --namespace {{ .Release.Namespace }} port-forward \
     svc/{{ include "latence-trace.fullname" . }} 8090:{{ .Values.service.port }}
   curl http://localhost:8090/agent-help
   curl http://localhost:8090/metrics | head -40

3. Wire Prometheus scraping:

{{- if .Values.serviceMonitor.enabled }}
   ServiceMonitor enabled -- kube-prometheus-stack will pick it up
   automatically once the labels match your release selector.
{{- else }}
   Set serviceMonitor.enabled=true (kube-prometheus-stack), or rely on
   the prometheus.io/scrape pod annotations the chart already emits.
{{- end }}

4. Calibrate thresholds against your domain:

   docs/operations/calibration-runbook.md walks through the
   ``latence-trace calibrate`` flow end-to-end.
